## Goal

Build `overlay.py` — the transparent click-through pointer overlay that animates a blue circle to UI elements Claude identifies in the user's screenshot. Must pass through clicks to underlying apps, not steal focus, not appear in the taskbar, and handle per-monitor DPI correctly on Windows 11.

## Architecture — per-monitor, not virtual-desktop-spanning

**The architectural reversal.** CLAUDE.md originally said "overlay spans full virtual desktop" — a single giant `QWidget` covering `(virtual_left, virtual_top, virtual_width, virtual_height)`. Research during brainstorming found Qt 6 High DPI docs explicitly warn:

> *"Qt will scale the screen size... but will not change the screen position. This will produce an 'islands-of-screens' type virtual desktop geometry on Windows with mixed DPI. Application code should not assume that a position immediately adjacent to and outside one screen is a valid position on the neighboring screen."*

**Impact:** a single widget spanning multiple monitors lands in gaps between screens when DPI differs (e.g., laptop at 200% + external monitor at 100% in Windows+P Extend mode). The pointer silently appears in the wrong place or nowhere — worst possible failure mode for a screen-aware AI whose entire UX is visual pointing.

**Fix:** **one `QWidget` overlay per physical monitor**, created by iterating `QGuiApplication.screens()`. Each overlay covers only its screen's `geometry()` in DIP coords. Claude's coordinates are routed to whichever screen matched the original `CaptureResult.monitor`. This is what `danpeg/clicky`, OBS Studio, and Ammad-Younas/Screen_Annotation all do.

See [DECISIONS.md § "Per-monitor overlays instead of virtual-desktop-spanning"](../../../DECISIONS.md) for the full rationale and alternatives considered.

## Design — 5 hard subproblems addressed concretely

### 1. Win32 flag application (click-through mechanism)

**The flags** (all live in `overlay.py` as `_WS_EX_*` constants, OR'd into `_CLICKTHROUGH_FLAGS = 0x080800A8`):

| Flag | Value | Purpose | Required? |
|---|---|---|---|
| `WS_EX_LAYERED` | `0x00080000` | Makes the window "layered" — required for `WS_EX_TRANSPARENT` to work on top-level windows | **Yes** |
| `WS_EX_TRANSPARENT` | `0x00000020` | The actual click-through flag | **Yes** |
| `WS_EX_TOPMOST` | `0x00000008` | Always on top | Harmless dup with `Qt.WindowStaysOnTopHint` |
| `WS_EX_NOACTIVATE` | `0x08000000` | Prevents focus theft when overlay receives any event | **Yes** |
| `WS_EX_TOOLWINDOW` | `0x00000080` | Hides from taskbar + Alt-Tab | **Yes** |

**Application order** (enforced by `apply_clickthrough_styles(hwnd)` in overlay.py):
1. Create `QWidget` with Qt flags + attributes
2. `setGeometry(screen.geometry())` (DIP coords)
3. `show()` — HWND now exists
4. `GetWindowLongW(hwnd, GWL_EXSTYLE)` → current flags
5. `new_style = current | _CLICKTHROUGH_FLAGS` (OR in, NEVER overwrite — would wipe Qt's own flags)
6. `SetWindowLongW(hwnd, GWL_EXSTYLE, new_style)` → apply
7. **Check return value. If 0 and `current != 0`, raise `RuntimeError` with `ctypes.WinError()`.** (Boris #5 addition — catches silent click-through failures.)
8. `SetWindowPos(hwnd, HWND_TOPMOST, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE | SWP_FRAMECHANGED)` — forces changes to take effect immediately

**Anti-patterns we explicitly avoid:**
- ❌ `Qt.WA_TransparentForMouseEvents` alone (not enough on Win 11 frameless transparent windows)
- ❌ `setStyleSheet("background: transparent")` (#1 flicker source on Win 11 per forum.qt.io)
- ❌ `setWindowOpacity(<1.0)` (forces Qt's own layered-window path, overrides ex-style changes)
- ❌ Applying ex-styles BEFORE `show()` (HWND doesn't exist yet, or Qt reapplies over yours)
- ❌ Overwriting `GWL_EXSTYLE` instead of OR-ing (wipes Qt's own flags)

### 2. DPI-aware coordinate math (three coordinate spaces)

Three spaces defined in the project:
- **Space A:** physical pixels from `mss` / `GetCursorPos` (virtual-desktop coords)
- **Space B:** Qt logical (DIP) pixels — what `QWidget.setGeometry` / `move` expect
- **Space C:** Claude's declared resolution (1024×768 / 1280×800 / 1366×768)

`capture.py` owns Space A ↔ Space C. `overlay.py` owns Space A ↔ Space B. `app.py` wires them together via `capture.unscale_claude_coords(Space C → Space A)` → `overlay.OverlayController.point_at(Space A → Space B local)`.

**Key function:** `physical_to_local_logical(physical_x, physical_y, screen: QScreen) -> tuple[int, int]` — maps a physical-pixel point to within-screen logical DIP coords. Uses PER-SCREEN `devicePixelRatio()` (never cached globally — mixed-DPI setups have different ratios per screen).

**Verified worked example on user's machine (2880×1800 @ 200% single monitor):**
- `QScreen.geometry()` = `(0, 0, 1440, 900)` DIP
- `screen.devicePixelRatio()` = `2.0`
- Claude returns `(640, 400)` in 1280×800 → `capture.unscale_claude_coords` → physical `(1440, 900)` (Step 1 ground truth)
- `physical_to_local_logical(1440, 900, screen)` = `(720, 450)` DIP
- Overlay widget covers `(0, 0, 1440, 900)` DIP, so `(720, 450)` = dead center ✓

### 3. Per-monitor architecture (controller + routing)

```python
class OverlayController:
    def __init__(self, overlay_factory=None, screens: list[QScreen] | None = None):
        if overlay_factory is None:
            overlay_factory = OverlayWindow
        if screens is None:
            screens = QGuiApplication.screens()
        self.overlays: list[OverlayWindow] = []
        for qscreen in screens:
            overlay = overlay_factory(qscreen)
            overlay.show()
            overlay.apply_win32_clickthrough()
            self.overlays.append(overlay)

    def point_at(self, physical_x: int, physical_y: int, monitor: dict) -> None:
        screens = QGuiApplication.screens()
        target_screen = screen_for_monitor(monitor, screens)
        target_overlay = self._overlay_for_screen(target_screen) or self.overlays[0]
        local_x, local_y = physical_to_local_logical(physical_x, physical_y, target_screen)
        target_overlay.animate_pointer_to(local_x, local_y)

    def _overlay_for_screen(self, screen: QScreen) -> OverlayWindow | None:
        for overlay in self.overlays:
            if overlay.screen_name == screen.name():
                return overlay
        return None

    def hide_for_capture(self) -> None:
        for overlay in self.overlays:
            overlay.hide()

    def show_after_capture(self) -> None:
        for overlay in self.overlays:
            overlay.show()
            overlay.apply_win32_clickthrough()  # re-apply in case Qt reset ex-styles
```

**Dependency injection.** `overlay_factory` and `screens` are injectable so unit tests can substitute mocks without a real `QApplication`. Production code never passes these; tests always do.

### 4. Pointer rendering — QPainter subclass

```python
class OverlayWindow(QWidget):
    def __init__(self, screen: QScreen) -> None:
        super().__init__()
        self.setWindowFlags(
            Qt.WindowType.FramelessWindowHint
            | Qt.WindowType.WindowStaysOnTopHint
            | Qt.WindowType.Tool  # no taskbar entry (Qt-level equivalent of WS_EX_TOOLWINDOW)
        )
        self.setAttribute(Qt.WidgetAttribute.WA_TranslucentBackground, True)
        self.setAttribute(Qt.WidgetAttribute.WA_NoSystemBackground, True)
        self.setAttribute(Qt.WidgetAttribute.WA_TransparentForMouseEvents, True)
        self.setGeometry(screen.geometry())
        self.screen_name = screen.name()
        self._pointer_pos = QPoint(0, 0)
        self._pointer_visible = False
        self._animation = QPropertyAnimation(self, b"pointerPos")
        self._animation.setDuration(400)  # config.POINTER_ANIMATION_MS
        self._animation.setEasingCurve(QEasingCurve.Type.Linear)

    def paintEvent(self, _event) -> None:
        if not self._pointer_visible:
            return
        painter = QPainter(self)
        painter.setRenderHint(QPainter.RenderHint.Antialiasing, True)
        painter.setBrush(QColor(30, 144, 255))  # dodger blue
        painter.setPen(QPen(QColor(255, 255, 255), 2))
        painter.drawEllipse(self._pointer_pos, 20, 20)

    def animate_pointer_to(self, local_logical_x: int, local_logical_y: int) -> None:
        target = QPoint(local_logical_x, local_logical_y)
        self._animation.stop()
        self._animation.setStartValue(self._pointer_pos)
        self._animation.setEndValue(target)
        self._pointer_visible = True
        self._animation.start()

    pointerPos = pyqtProperty(QPoint, _get_pointer_pos, _set_pointer_pos)
```

**Why `QPainter` + `paintEvent`, not `QLabel` + PNG or `QGraphicsView`:**
- `QPropertyAnimation` drives a `pyqtProperty` cleanly at 60 fps
- No second paint pipeline (unlike `QGraphicsView`)
- Full anti-aliasing control
- Works with `WA_TranslucentBackground` without flicker
- Simplest implementation — single widget, single paint callback

**`_event` parameter naming:** Qt's API requires the parameter in the signature even though we don't use it. Leading underscore (`_event`) is PEP 8 convention for intentionally unused parameters — cleaner than a `# noqa: ARG002` suppression.

## Risks and mitigations

| # | Risk | Mitigation |
|---|---|---|
| 1 | PyQt6 click-through silently fails on user's GPU driver | Pre-committed tkinter+pywin32 fallback path; user tests on real desktop |
| 2 | Win32 flag constants mistyped | Task 2 sanity test asserts OR bit pattern is `0x080800A8` |
| 3 | Flag application before `show()` doesn't take effect | Applied from `OverlayController.__init__` AFTER `overlay.show()`; re-applied in `show_after_capture()` in case Qt resets |
| 4 | `SetWindowLongW` silently fails | Boris #5 fix — raises `RuntimeError` with `ctypes.WinError()` context |
| 5 | Stylesheet-based transparency causes flicker | Use `WA_TranslucentBackground` + `WA_NoSystemBackground` attributes; NO `setStyleSheet` |
| 6 | `setWindowOpacity()` overrides ex-styles | Never called; opacity stays at 1.0 default |
| 7 | Mixed-DPI coordinate math lands in islands-of-screens gap | Per-monitor architecture eliminates virtual-desktop spanning; within-screen local coords only |
| 8 | Pointer shows in screenshots sent to Claude | `hide_for_capture()` called by `app.py` before every `mss.grab()` (Step 7 concern, API locked here) |
| 9 | Overlay persists after app crash | PyQt6 process death cleans up windows; Phase 2 can add signal handlers |
| 10 | User has only one monitor, multi-monitor code path unverified | Documented in DECISIONS.md; Phase 2 or whenever user plugs in external display verifies real multi-monitor |
| 11 | `hide_for_capture()` / `show_after_capture()` breaks silently, Claude sees own pointer | Boris #5 fix — `TestOverlayControllerLifecycle` covers both methods |
