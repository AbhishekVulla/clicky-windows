# `ai.py` Design Spec

**Component:** Step 2 of Clicky Windows Phase 1
**Status:** Brainstorm locked 2026-04-11, awaiting execution
**Author:** Abhishek + Claude Opus 4.6 (Superpowers brainstorming ceremony)

## Purpose

`ai.py` is the vision+LLM layer of Clicky Windows. It takes a resized screenshot + user voice transcript + session history, calls Claude Sonnet 4.6 via the Computer Use API beta, and returns both a natural-language response (for TTS) and pixel coordinates (for the animated pointer overlay).

It is the second link in the core loop: `capture.py` (Step 1 ✅ done) → **`ai.py` (Step 2, this spec)** → `overlay.py` (Step 3) + `tts.py` (Step 5) → `memory.py` (Step 6.5) → `app.py` (Step 7 orchestrator).

## Why this design exists

**The question:** *"When we send a screenshot to Claude, how do we get pixel-accurate coordinates back?"*

**The answer, proven by the upstream Clicky macOS app:** Claude's Computer Use API beta activates specialized pixel-counting training that is **significantly more accurate** than parsing coordinates out of Vision API text responses (verified by reading `leanring-buddy/ElementLocationDetector.swift` line-by-line on 2026-04-11).

**The design principle:** mirror Clicky exactly. Do not invent. Do not reword the prompt. Do not deviate from the tool JSON shape. Clicky has thousands of real users hitting these exact parameters — we inherit that validation for free, and any deviation is a risk we don't need to take in Phase 1.

## Architecture

### Public surface — provider abstraction

```python
class AIClient(ABC):
    """Abstract base for vision+LLM providers.

    Phase 1: AnthropicClient (Computer Use API beta, Anthropic-direct).
    Phase 2: OpenRouterClient (vision-tag regex fallback — no beta on OpenRouter).
    """
    @abstractmethod
    def ask(
        self,
        image: Image.Image,
        transcript: str,
        history: list[dict],
        declared_w: int,
        declared_h: int,
    ) -> dict:
        """Return {"text": str, "points": [{"x": int, "y": int, "label": str}]}.
        Coordinates are in (declared_w × declared_h) space (Space C), unscaled —
        the caller uses capture.unscale_claude_coords() to map to physical pixels.
        """


class AnthropicClient(AIClient):
    def __init__(self, api_key: str, model_id: str): ...
    def ask(self, image, transcript, history, declared_w, declared_h) -> dict: ...
```

### Internal helpers (module-level, independently testable)

```python
def build_user_prompt(transcript: str) -> str: ...
def image_to_base64_jpeg(img: Image.Image, quality: int = 85) -> str: ...
def parse_tool_use_coordinates(response) -> list[tuple[int, int]]: ...
def parse_response_text(response) -> str: ...
```

**Dual-access pattern:** `parse_tool_use_coordinates` and `parse_response_text` must accept BOTH the `anthropic.types.Message` object (production) AND plain `dict` shapes (test mocks). Implemented via `getattr(block, "type", None) or block.get("type")`. One function body handles both — tests stay dict-based (cheap, no SDK mocking), production uses real SDK objects.

### Data flow

```
CaptureResult.image (PIL, 1280x800)
CaptureResult.target_width / target_height
user transcript (from stt.py)
session history (list of dicts, owned by app.py)
                    |
                    v
           AnthropicClient.ask()
                    |
       +------------+------------+
       |                         |
       v                         v
image_to_base64_jpeg      build_user_prompt
       |                         |
       +-----------+-------------+
                   v
      client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=256,
        tools=[{"type": "computer_20251124", ...}],
        extra_headers={"anthropic-beta": "computer-use-2025-11-24"},
        messages=[*history, {role, content:[image, text]}],
      )
                   |
                   v
           anthropic.types.Message
                   |
       +-----------+-------------+
       |                         |
       v                         v
parse_tool_use_coordinates  parse_response_text
       |                         |
       +-----------+-------------+
                   v
{"text": "...", "points": [{"x":int,"y":int,"label":""}]}
                   |
                   v
              (returned to app.py)
```

## Design decisions (10 locks)

1. **API shape: verbatim Clicky mirror.** Headers, tool JSON, system prompt, max_tokens — all copied byte-for-byte from [reference_clicky_computer_use_api.md](../../../../.claude/projects/c--Users-Abhis-OneDrive-Documents-Clicky-Windows/memory/reference_clicky_computer_use_api.md), which was itself extracted directly from `farzaa/clicky/leanring-buddy/ElementLocationDetector.swift` via `gh api` in this session. Zero deviation. [DECISIONS.md § "Use Claude Computer Use API beta directly"](../../../DECISIONS.md) rejects vision-tag regex fallback.

2. **Anthropic SDK, not raw httpx.** SDK v0.94.0 is installed and supports `extra_headers`. Raw HTTP duplicates auth, retries, response typing for zero benefit.

3. **Dual-access response parsing.** `getattr(block, "type", None) or block.get("type")` pattern in both parsers. Tests use dict mocks; production uses SDK objects; same function body handles both.

4. **`history` contract: Anthropic SDK message format.** `list[dict]` where each dict is `{"role": "user"|"assistant", "content": [...]}`. `app.py` owns the list and appends both user and assistant turns after each call. `ask()` just does `messages=[*history, new_user_turn]`. History is opaque to `ai.py`. Phase 2's `memory.recall()` will mutate this list (or wrap it) before calling `ask()`.

5. **Return shape: `{"text": str, "points": [{"x":int,"y":int,"label":str}]}`.** Coordinates in Claude's declared-resolution space (Space C), unclamped. Caller (`app.py`) passes them through `capture.unscale_claude_coords()` to map to physical pixels. `label` is empty string in Phase 1 — Clicky's Computer Use tool returns only `left_click` coordinates, no labels.

6. **Errors propagate.** `anthropic.APIError`, `anthropic.RateLimitError`, network errors all bubble up to `app.py` which surfaces them to the user. No retry logic, no exponential backoff, no fallback chains in Phase 1. Simpler code, failures visible.

7. **Token counts printed in `__main__` only.** Not exposed in the return dict. Keeps `ask()`'s public contract minimal. Phase 2 can add a `usage` key if cost tracking becomes important.

8. **Timeout 15s** (mirroring Clicky's `timeoutIntervalForRequest: 15`). Set via `Anthropic(api_key=..., timeout=15.0)` in `AnthropicClient.__init__`. If Claude doesn't respond in 15s the user has already given up; better to fail fast than hang the UI.

9. **`build_user_prompt` byte-for-byte verbatim.** f-string with triple-quoted template matching reference memory exactly. Tests assert three anchor phrases (`"looking at their screen"`, `"If there is a specific UI element"`, `"no specific element"`) verbatim so drift is caught immediately.

10. **NOT using the SDK `system=` parameter.** Clicky co-locates the instructions with the image in the user content block, not as a top-level system prompt. Computer Use training was done with this layout; moving instructions to `system=` may degrade accuracy. Do not deviate until we have a reason.

## Approaches considered and rejected

| Approach | Pros | Cons | Verdict |
|---|---|---|---|
| **A. Anthropic SDK + verbatim Clicky mirror** (chosen) | Matches proven reference implementation, dual-access parsers reuse across prod + tests, SDK handles auth/typing | Anthropic-direct only, locked to Computer Use beta | **Picked.** Boring, safe, copy what works. |
| B. Raw httpx + hand-rolled JSON | Full control, no SDK dependency | Duplicates auth/retry logic, larger test surface, zero benefit | Rejected — over-engineering. |
| C. Computer Use agent loop (multi-turn with screenshot iteration) | More autonomous, Claude can "scroll and look" | 5-10× cost, 15-30s latency, wrong category for "ask once answer once" UX | Rejected — Clicky isn't an agent. |
| D. Vision API only + `[POINT:x,y]` regex fallback (the `[POINT]` tags approach) | Works through OpenRouter, no beta header | ~20% less accurate per Clicky's own code comment, not used by upstream, only exists as a hypothetical Phase 2 OpenRouter compat path | Rejected — see [DECISIONS.md](../../../DECISIONS.md) § "Use Claude Computer Use API beta directly, not vision-tag regex fallback". |

## Verbatim Clicky system prompt

```
The user asked this question while looking at their screen: "<USER_TRANSCRIPT>"

Look at the screenshot. If there is a specific UI element (button, link, menu item, text field, icon, etc.) that the user should interact with or is asking about, click on that element.

If the question is purely conceptual (e.g., "what does HTML mean?") and there's no specific element to point to, just respond with text saying "no specific element".
```

`<USER_TRANSCRIPT>` is substituted at call time. Whitespace and wording are exact — the reference memory is the source of truth.

## Verbatim Clicky API call shape

```python
message = client.messages.create(
    model=self.model_id,                 # "claude-sonnet-4-6" from config
    max_tokens=256,
    tools=[{
        "type": COMPUTER_USE_TOOL_TYPE,  # "computer_20251124"
        "name": "computer",
        "display_width_px": declared_w,
        "display_height_px": declared_h,
    }],
    extra_headers={"anthropic-beta": COMPUTER_USE_BETA},  # "computer-use-2025-11-24"
    messages=[*history, {
        "role": "user",
        "content": [
            {
                "type": "image",
                "source": {
                    "type": "base64",
                    "media_type": "image/jpeg",
                    "data": base64_jpeg,
                },
            },
            {"type": "text", "text": build_user_prompt(transcript)},
        ],
    }],
)
```

**Non-negotiables:**
- `extra_headers={"anthropic-beta": "computer-use-2025-11-24"}` — without this, Computer Use doesn't activate and pixel accuracy drops
- `tools=[{"type": "computer_20251124", ...}]` — exact string
- `display_width_px` / `display_height_px` **must match** the resized image dimensions actually sent (caller passes `CaptureResult.target_width` / `.target_height`)
- `history` is prepended as-is; the new user turn is always appended last

## Canonical file order (mandatory)

Per [feedback_main_block_ordering.md](../../../../.claude/projects/c--Users-Abhis-OneDrive-Documents-Clicky-Windows/memory/feedback_main_block_ordering.md), `ai.py` is written top-to-bottom in dependency order to avoid the `NameError` bug `capture.py` hit:

1. Module docstring
2. `from __future__ import annotations` + imports
3. Constants (most live in `config.py` — minimal additions here)
4. Helper functions: `build_user_prompt`, `image_to_base64_jpeg`, `parse_tool_use_coordinates`, `parse_response_text`
5. `AIClient` abstract base class
6. `AnthropicClient` concrete class
7. `if __name__ == "__main__":` block — **LAST**

## Testing approach

**16 unit tests, all mock-based, target green in <2s.** Breakdown:
- `test_ai_module_importable` (1)
- `build_user_prompt` — verbatim template, transcript substitution, empty transcript (3)
- `image_to_base64_jpeg` — ASCII string, valid base64 JPEG magic bytes, quality parameter (3)
- `parse_tool_use_coordinates` — single, multiple, empty, non-left_click filter (4)
- `parse_response_text` — single text block, multiple blocks joined (2)
- `AIClient` abstract — cannot instantiate (1)
- `AnthropicClient.ask` — SDK call args, return shape, history prepended (3)

**Running total after Step 2:** 22 (capture) + 16 (ai) = **38 tests** trending toward the Phase 1 ~50-80 target.

**Zero real-API dependency in unit tests.** `mocker.patch("ai.Anthropic")` injects a fake SDK client. The fake `.messages.create` returns dict-shaped responses compatible with both parsers (proving the dual-access pattern works).

## Live-API acceptance gate (not a unit test)

`python -m ai` uses the real `.env` key and `debug_capture.jpg` (generated in Step 1 verification) to prove the full pipeline works end-to-end against live Anthropic. Prints response text + points + in-bounds check. **User visually confirms** that the returned coordinate lands on a plausible UI element in `debug_capture.jpg`.

This is Step 2's answer to Step 1's red crosshair test — the real-world proof that must pass before the commit.

## Out of scope for Step 2 (Phase 2 or later)

- **Streaming responses** — Phase 1 is blocking; TTS starts only after full response
- **Retry logic / exponential backoff** — errors propagate to `app.py`
- **OpenRouter / vision-tag regex fallback** — Phase 2 via `OpenRouterClient(AIClient)` subclass
- **Memory recall injection into the prompt** — that's Step 6.5 (`memory.py`) + Step 7 (`app.py`) wiring, not Step 2. `history` is just the in-session list for now.
- **Label extraction** — Computer Use returns only `coordinate`, no labels
- **`history` trimming / token budget management** — Phase 2
- **Token usage in return dict** — Phase 2 (`usage` key)

## Risks and mitigations

| # | Risk | Mitigation |
|---|---|---|
| 1 | Anthropic SDK response shape differs from dict mocks | Dual-access pattern in both parsers; live call at Task 8 validates. |
| 2 | `anthropic-beta` header ignored by SDK 0.94.0 | `extra_headers` is supported from SDK ≥ 0.40.0; confirm via live call that coordinates are pixel-accurate not drifted. |
| 3 | Image base64 payload too large | JPEG quality 85 keeps ~1280×800 images under 200 KB, well below 5 MB API limit. |
| 4 | Real API costs during iteration | Print token counts after every live call; temporarily swap to `claude-haiku-4-5` in `.env` for iteration; switch back to `claude-sonnet-4-6` for final acceptance. |
| 5 | Parser breaks on SDK upgrades | Tests cover both dict and SDK-object shapes; `anthropic>=0.40.0` pinned. |
| 6 | Rate limit during live test | Single `__main__` call; manual retry if 429. |
